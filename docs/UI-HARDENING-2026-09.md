# UI hardening — September 2026

This release implements the September UI audit as shared component changes,
not a new visual theme or a platform rewrite. The restrained indigo/neutral
palette stays; muted light-mode text is slightly stronger for readability.

## What changed

- **Layout:** zero-minimum grid sizing on sign-in, wrapping page-header actions,
  bounded profile selectors, and a viewport-sticky application header. Horizontal
  scrolling is local to intentional tab strips/tables, not hidden on the app shell.
- **Themes:** one reactive theme store used by Settings, header and commands;
  pre-paint initialization, device preference tracking in System mode, cross-tab
  synchronization, and graceful storage-unavailable behavior. Sift uses semantic
  colors for both light and dark controls instead of forcing a dark island.
- **Navigation:** native modal drawer with an accessible name, inert background,
  focus entry/containment/restoration, Escape/outside dismissal, desktop resize
  dismissal, safe-area spacing, and scrolling on short screens. Focus containment
  is shared with the workspace dialog.
- **Forms:** compact horizontally scrollable profile sections, reduced nested
  mobile padding, full-width benchmark fields, and a full-width mobile workspace
  explanation with clearly separated Create/Cancel actions. Delete profile is in
  a secondary management section, still using the existing confirmation flow.
- **Hierarchy:** one page title for invoice review and a concise invoice-context
  heading, rather than multiple competing workspace titles.
- **Honest states:** the public demo explains why it cannot generate a posting
  plan without making a rejected request. Read-only Settings are disabled before
  interaction; existing backend permission enforcement remains unchanged.
- **Copy/accessibility:** named Settings selectors, stronger helper-text contrast,
  current extraction-evidence wording, accurate AI context disclosure, and no
  advertised profile wizard that does not exist.

## Verification

The release is checked against an isolated localhost API and SQLite database.
Synthetic organizations, PDFs and invoices are used; no production client data,
emails, accounting credentials or live postings are involved.

- Backend: **285 tests passed**. Only existing SWIG/Python deprecation warnings.
- Web: typecheck, lint and production build.
- Browser suite: **49 tests**, including the existing approval-plan, master-sync,
  extraction-evidence and reporting regressions plus **14 new UI tests**.
- Sign-in control bounds: 320, 375, 390, 768, 1024 and 1440px in both themes.
- All 20 top-level product routes: 375, 768 and 1024px in both themes; existing
  core-workflow tests also cover 320, 390 and 1440px. This is not every possible
  data/state combination.
- Owner fixtures cover two long profile names, mobile form widths over 230px,
  a USD 11,800,000 invoice in Sift, editable workspace defaults, and dialog layout.
- Read-only demo tests verify that posting-preview requests are not sent and
  workspace preferences cannot be edited. Theme tests cover persistence and
  device changes; focus tests cover both forward and reverse keyboard traversal.
- A targeted axe-core WCAG A/AA scan of Home, Rules, Review, Settings, Client
  profiles and Tally integration in both themes found no violations after fixes.
  This is a targeted automated check, **not a WCAG certification**.

Screenshots and individual test results are generated by Playwright and retained
as CI artifacts. Individual element bounds are checked, not only document width.

## Deployment and boundaries

Normal web deployment; no database migration, Railway variable change, connector
reconfiguration or Windows installer upgrade is needed for this release.
Approval plans, mandatory approval, connector execution and reconciliation logic
are unchanged. Profile settings and legacy onboarding samples are preserved.

Before declaring universal device acceptance, check real iPhone Safari/Android
Chrome with the on-screen keyboard and any supported Windows display scaling.
The existing real Windows/Tally posting acceptance gate remains separate from
this web UI release. Unseen layouts and assistive-technology combinations still
need representative user testing.
